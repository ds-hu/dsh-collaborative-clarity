Variant A · no build

The repository is the package

Every file the harness loads sits at the root, exactly where package.json is. Nothing is generated; what is committed is what runs.

Install

# this checkout
dsh plugin --profile web add \
  link:D:/Projects/dsh-collaborative-clarity

# any machine, no path
dsh plugin --profile web add \
  github:ds-hu/dsh-collaborative-clarity

No prepare, no dependencies, no allowBuilds line to approve. pnpm clones, links, done.

What it costs

  • The root has generic names. index.js is the host entry only because package.json says so — a reader opening the folder sees neither src/ nor plugin/ to orient them.
  • No type checker, no bundler. One typo in 1,349 lines of client.js is caught by the tests or by the browser, not by a compiler — and the loader wrapper (window.__ModuleLoader__.load) stays hand-written.
  • Splitting the client half later means adopting Variant B, on top of a working plugin rather than instead of writing one.
The profile entry has to be removed and re-added once: the installed link points at …/plugin, which no longer exists. The row id and the browser bundle id do not change.
