Collaborative Clarity

npmv0.3.2 downloads818/month licenseApache-2.0 DeepSeek Harnessplugin

A right-sidebar tab where the agent shows you a decision instead of describing one — and waits, inside the tool call, until you have answered it.

What goes wrong when you vibe code

Handing the build to an agent is fast, and three things go wrong in the same way each time. None of them is a badly worded prompt; each is a missing object.

  • You meet the interface late. The agent decides how a screen behaves, builds it, and you see it when it is finished — so the disagreement arrives as rework. A round puts the screen in front of you before it is built.
  • The architecture becomes someone else's. Hand the code over wholesale and you lose the map: which choice is risky, what it costs, and why it was made stay invisible until a user finds them for you. A round carries the ten lines that matter, a recommendation, and what that recommendation forecloses.
  • Green tests stand in for a real test. A unit test asserts what its author imagined. The repeated, hands-on checking a developer does while building does not survive as a test case. A round ends at a gate a human has to run.

This plugin supplies the object. The agent writes the smallest file that makes one decision concrete — a screen, a type, a function — opens it in the right sidebar, names the variant it recommends, and says what that choice forecloses. Then it waits.

The unit of collaboration becomes a round: one decision, one artifact set, one wait, one record. Everything else here follows from that sentence.

A round, end to end

  1. The agent puts the decision on screen. Two variants at most, each a real file rather than a description of one.
  2. You point at what you disagree with. Click an element, drag-select a phrase, or click a line. The comment keeps its location, so “this label is wrong” arrives with the label attached.
  3. You decide. Accept, revise, reject, or decide later. Your annotations and the chosen variant come back to the agent as structured data, not prose it has to interpret.
  4. The agent writes the decision down. The verdict, the foreclosures you accepted, and every comment still open land in the repository beside the artifact.

The last step is a real test

clarity_test opens the gate after the build. The agent records the build it has already run, hands you one command to bring the app up, and writes down a scenario of three to seven steps. You run it, you look, and you record what happened — pass, fail, or blocked — with screenshots when the words alone are ambiguous. Until then the change is built, not tested.

Install

dsh plugin --profile web add @ds-hu/dsh-collaborative-clarity

Requires DeepSeek Harness with the web profile. From a checkout, add link:D:/path/to/dsh-collaborative-clarity instead; from GitHub, github:ds-hu/dsh-collaborative-clarity. There is no build step and one runtime dependency (markdown-it). Non-blocking rounds also need @deepseek-ai/dsh-tool-jobs in the profile.

The version is 0.x, and what works is written down rather than implied: 06-implementation.md lists the verified surfaces and the remaining gaps.

What a round leaves behind

Round recordThe decision, the recommendation, and the foreclosures you accepted
AnnotationsWhat you pointed at, and whether it was resolved
Test recordWho ran the scenario, and what they saw

The artifact itself is disposable evidence. The tab is not a document store.
