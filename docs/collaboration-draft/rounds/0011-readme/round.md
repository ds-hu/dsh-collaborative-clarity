# Round 0011 — README 改成"为什么 + 怎么用"

**Decision:** README 该继续当参考手册，还是改成先讲为什么、再讲怎么用的短文档？
**Variant A:** *The argument first* — 论证在前，界面图在后；机制细节搬进新的 AGENTS.md。
**Variant B:** *The screen first* — 徽章下面立刻是截图，哲学压到第二节。
**Recommendation:** A.
**Accepted:** A，三轮 revise 后定稿为 A‴。
**Forecloses:** ① 机制细节搬走后，没有一个文件能一页查全参数，读 README 的人要多跳一次；
② 英/中两份加 AGENTS.md 三处同源，每次机制改动要同步，中文侧会先腐化；③ 首屏用 "vibe
code" 一词，读者若视其为贬义，第一屏先把人分成了两边；④ hero 只有这一处，拍砸了没有第二张救。

## Why this round

README 长成了手册：189 行，从安装一路铺到 `/clarity/api` 的路由形状、prompt section 的
order、七个测试文件的分工。这些都是真的，但它们回答的是"这东西怎么长出来的"，不是"我要不要
装它"。

用户要的是反过来：先讲为什么有这个东西，再讲怎么用；配截图和徽章；再给一份中文版；机制细节
挪到 AGENTS.md。于是这一轮要定的其实只有一件事——首屏放论证还是放界面。两版文案完全相同，
差别只在顺序，所以它能被并排看。

## Addendum — 2026-11-05

定稿之后用户又直接追加了三条核心观点，位置由我定。三条都进了新的 `## Why it works`，放在
"round 的定义"之后、"一个 round，从头到尾"之前：

1. **artifact 不必是你的产品** —— HTML 最容易渲染、覆盖面也最广，所以非网页的项目照样能用
   一个网页把它演出来。
2. **两边的强项正好相反** —— agent 不擅长长的工具循环（缓存命中也是成本），擅长一次生成；
   人不可能一口气写出整页 HTML，也不愿在已有实现之外重写一份。互补。
3. **最后一公里是人** —— 东西最终要交给用户，开发者得先自己体验。

放这里是因为前两条解释"这套机制凭什么成立"，第三条正好把话头交给下面那道测试关。

中文版重写过一次。第一版是对着英文逐句翻的，句子结构、被动语态、长定语全是英文的，读起来是
译文腔；第二版按中文重写：同样的内容，句子重新断，能用主动就不用被动，标点换成全角。以后改
中文版，也应该按中文写，而不是先改英文再翻。
