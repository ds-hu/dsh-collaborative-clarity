为什么只要两行 气泡是索引，不是记录

  • 回头扫对话时，唯一想立刻知道的是「这一轮最后定了什么」。答案是一行。
  • 批注可能三五行，带上锚点更长；塞进气泡会把整段对话顶开，读起来像正文。
  • 它已经存在三处：面板、工具行、rounds/ 记录。气泡再抄一份，就多一处会旧。

机制 浏览器半边，不动宿主

  • 定义：匹配本工具自己的 tool/call 与 tool/result，从结果 JSON 里取出裁决。
  • 节点：kind: 'clarity-decision'，groupTree: 'turn'，与 ask_user 气泡同一位置与口径。
  • 渲染：一个 keyed slot 占位，气泡用 UserMessageBubble，缺这个原语时退到自带样式。

形状

match(event):
  tool/call   name === 'clarity_round'  -> start(callId)
  tool/result surfaceOp === 'append'    -> update(callId)

start  -> { decision, labels }
update -> 解析 content[0].text 的 JSON
          status !== 'decided' ? 无 : {
            verdict, variantLabel, time, seq }

buildViewNode:
  verdict 为空            -> null      // 没有决定就没有气泡
  否则 -> { kind:'clarity-decision',
            anchorSeq: seq,
            groupTree: 'turn',
            visibility: 'visible',
            data: { decision, verdict,
                    variantLabel, time } }

失败时 气泡永不挡住工具行

硬规则

  • 只从会话事件推导：不读插件 store，不发网络请求，不点出任何工具调用。
  • 不加 exclusive：工具行必须同时在，inspect 和重开都靠它。
  • 定义是纯函数；同一段历史重放，必须得到同一个节点。
  • 文案只进 MESSAGES 双表（en/zh 键集相同），渲染函数里没有字面量。
