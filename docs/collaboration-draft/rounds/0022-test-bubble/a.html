为什么只写结论 结论是一个词，观察是一段话

  • 扫对话时想知道的是「测过没有、过没过」。候选 + 一个词就答完了。
  • 观察是你刚在测试闸门里写的那一两句话，紧接着再在对话里读一遍，是把同一段字读第二次。
  • 证据的家在工具行（它同时带着 prepared 与命令）和 rounds/<NNNN>/test.md。

机制 与决定那条共用一个定义

  • decisionNode 多认一种 start：clarity_test 的 tool/call。
  • update 多收一种结果：status: 'tested' 且 verdict 是 pass / fail / blocked。
  • payload 加一个判别字段（kind: 'decision' | 'test'），仍然只注册一个 keyed 渲染器；判定沿用同一条：认不出的裁决就不画。

失败时 与现在同一条规矩

闸门被取消没有气泡
结果不是 tested，或裁决认不出没有气泡，工具行照旧
观察很长不影响：它不进气
代价：想读「当时看到了什么」要多点开一次工具行；一次工作现在可能留下两条气泡， 扫的时候是两行，不是一行。
