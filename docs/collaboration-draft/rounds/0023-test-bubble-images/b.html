为什么图也值得进 截图是这次测试最硬的证据

  • 观察是「我看到了什么」，截图是「我凭什么这么说」。分开两处，等于让读的人自己拼。
  • ask_user 的气泡把用户写的东西原样再显示一遍；测试气泡照着同一个立场做，图和字一起。
  • 工具行迟早被过程组折叠；折叠之后，留在对话里的应当是完整的那一条。

机制 要动宿主半边

宿主 POST /test截图不再只写 .clarity/screenshots/…，另经 ctx.attachments.saveImage 存成会话附件
工具结果screenshots 从 { path, bytes } 变成附件引用（旧的形状并存一版，老轮次照样能读）
气泡用 ctx.uiConversation.imageUrl(sessionId, ref)（或节点自带的 loadImage）取地址，点开看大图
面板它本来就用内存里的 data URL 预览，不受影响

代价 这是 B′ 的账

  • 宿主改一次、结果 schema 变一次；clarity_test 的返回形状跟着动。
  • 同一张图会被存两份（项目目录里的 PNG + 会话附件），除非把它彻底搬走——搬走之后工具行里的图要另接一条路。
  • 气泡变高：一段观察加两枚 86×56 的缩略图。窄屏（360px）下要和气泡最大宽度配合，得真机看一眼。
  • 附件是给「人附上的图」设计的：归一化、有配额、随会话存储。拿它存工具产物是否越界，这一轮就得认下来。
