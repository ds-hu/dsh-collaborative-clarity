  • 顺手把「工具行看不到图」也修了：附件引用一进结果，ui-tool 的画廊自己就长出来。

它的账 第一条就够重了

  • 工具结果的 render 是模型可见的内容：图进了结果，模型下一轮也会收到这些图—— 这是替人留下的证据，却要按 token 记在模型的上下文里，还要跟着压缩、重算缓存。
  • 宿主半边要改：/test 多走一次 ctx.attachments.saveImage， clarity_test 的结果形状从 { path, bytes } 变成附件引用。
  • 附件是给「人附上的图」设计的：归一化、有配额、随会话存储。拿它存工具产物，等于把那条通道的含义改了。
  • 同一张图会存两份：项目目录里的 PNG + 会话附件。

机制

宿主POST /test 里调 ctx.attachments.saveImage，结果里带 ref
工具render 返回带图的内容块 → 工具行画廊 + 模型上下文都拿到图
气泡用 imageUrl(sessionId, ref) 或节点自带的 loadImage 画缩略图
如果只是想要「点开能在边栏看图」，A″ 已经够了，而且不动宿主、不进模型上下文。 B″ 换来的唯一额外好处是「不点也看得见图」。
