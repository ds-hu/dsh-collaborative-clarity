RoundStore 不再只管开着的轮。每个会话的每一轮——开着的、结算的、取消的—— 都留在内存里，/rounds 一并给出。tab 翻的就是这本账。

出发点了：今天的 tab 记着五样 （A 也从这里出发）

state.round屏幕上这一轮
sent我刚把决定送出去了

paramRoundId打开 tab 时带的 id
autoOpened这个会话这一轮我已经开过 tab 了

五处互相对账；每次 SSE 事件都重跑一遍 load()。 结算过的那一轮，只有 tab 自己还记着 id 时才看得到。

tool ──► RoundStore.rounds（Map，今天就已经不过期）
              │ 开着的 + 结算的 + 取消的，HTML 都在
              ▼
        GET /rounds?sessionId ──► 列表 ──► cursor

记录就是轮对象本身：variants[] 连同 html、 recommendation、cost、result。今天它已经在内存里，只是没人读。

改完以后，tab 只记一样

cursor住在 navigation.params.roundId 里。打开 tab 今天就是这么开的 （openTab(KIND, { params: { roundId } })）；翻到哪一轮＝改这个参数。刷新、撤销、再打开，都回到同一轮。

屏幕上是哪一轮cursor；没给就是列表最后一条

列表/rounds 一次给全

sent、 knownRound、 autoOpened、 load() 里「没开着的就回去找旧的」那一支——全删。

不变量 · 失败模式

  • 记录就是轮对象——没有第二份描述要同步。
  • 取消的轮、非阻塞的轮都在，带着原因。
  • 能回放当时的 mock，和你决定时看到的一字不差。
  • 进程一重启，账本清零。隔天复盘看到的是空列表。
  • 内存只增不减：每轮两份 HTML（各最多 400 KB）× 所有会话 × 进程寿命。要加淘汰；淘汰就意味着历史会在某一轮悄悄断掉。
  • 和日志是两份记录：同一个决定，气泡读日志、tab 读账本。不变量 7 写的就是这件事的反面。
  • 宿主注释原话「persisting the HTML would make a stale surface survive a restart」——这里没落盘，但让它在内存里活了一整个进程。

代价

  • 重启就没了。隔天、换机器、下次打开——正是最想复盘的时候。
  • 每会话每轮两份 HTML 留在内存里，得定一个淘汰数；定了数，历史就会在某一轮悄悄断掉。
  • 同一个决定两处记（日志一份、账本一份），迟早说不到一块。
  • 翻转了宿主「轮次是短命的」这条设计：一个过期的界面活一整个进程。
  • 真要跨重启，还得加一条落盘——一个新文件格式、一条写路径、一套清理规则。
想要回放、又想要重启后还在，那是第三条路（落到 .clarity/rounds/）——B 的全部代价再加一个 schema。这一轮不摆它。
